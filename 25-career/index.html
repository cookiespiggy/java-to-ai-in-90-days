    25 · 简历与面试：把工程经验翻译成 AI 语言¶

    先讲给朋友听（如果你只有一分钟）¶

    简历不是“我学过什么”的清单，是“我能替你解决什么”的合同草稿。你手里最值钱的，不是那三个月学的 Python，是那五年的工程履历——今天只做一件事：给它换上一套 AI 时代听得懂的语言系统。

    你的 Aha Moment¶

    两段简历，同一个人的两种死法：

    版本 A（自杀式写法）：

    熟练掌握 Python，熟悉 LangChain / LangGraph，
了解 RAG、Agent 开发，学习过大模型微调（LoRA）...

    HR 的内心 OS：又一页培训机构模板。跟另外 30000 份被打包丢进“AI应用开发”池子的简历，没有任何区别。

    版本 B（谈判式写法）：

    主导企业级 RAG 知识库系统落地：
- 构建 12 万页 PDF 知识库流水线（结构感知分块 + BGE Embedding + pgvector），
  检索 top1 命中率 94%（评测集 200 条驱动）
- 设计 Prompt 版本灰度体系，变更事故平均恢复时间从小时级降至 5 分钟
- 全链路 token 计量与降级熔断，单次问答成本下降 62%
- 基于 Java 8 的现有网关嵌入 AI 能力，混合栈零故障上线

    同样的技能点，一个在描述学习过程，一个在描述战斗结果。 Aha 就在这：市场不为“知识”付钱，为“风险被消除”付钱。 招 AI 应用工程师的公司真正怕的是——模型效果不稳、token 成本失控、线上炸了没人会修。你的 Java 工程履历不是过去式，是这三个恐惧的全部解药。

    第二个 Aha，关于差异化：培训机构批量产的是“会调 API 的 A 版简历”，供给正在过剩；你能供给的 B 版——工程底座 + AI 能力——市场上还是稀缺的。 别用你的短板去撞人家的长板。

    不讲术语的版本：简历、项目、面试三件套¶

    第一件 · 简历结构（三段式）。

    [头部] 5年Java后端工程师 → AI 应用工程方向（一句话定位）

[工程底座 - 60%篇幅，老战场] 
  高并发网关 / 微服务治理 / 线上问题排查，照实写，这是你的护城河

[AI 项目区 - 30%篇幅，新战场]
  2-3 个项目，每个按 STAR + 数字展开

[技术栈]
  Java 8, Spring Cloud | Python, LangGraph, pgvector, RAG, LoRA

    注意比例：别把 AI 项目写得比工程经历还重——那是舍本逐末，面试官会怀疑你的深度。最佳叙事是“带着工程能力的降维者”，不是“从零开始的转行者”。

    第二件 · 项目从哪来（没 AI 岗位也能攒）。

    本书一路的实战，组合起来就是一个完整项目：

    组合篇章 变成项目
    13 + 16 + 17 篇 企业知识库 RAG 系统（练手核心，简历主角）
    14 + 15 篇 HR 制度问答 Agent（工具调用 + LangGraph 编排）
    18 篇 模型风格微调实验（加分项，证明有炼丹常识）
    11 + 19 篇 OpenAI 兼容网关（展示后端老本行的迁移）

    四个项目串成一条故事线：从接入、到检索、到编排、到部署运维的完整闭环。 面试时讲“我做过一条龙”，比堆七个 Demo 有说服力得多。

    第三件 · 数字从哪来（没上线的项目也要有数）。

    没用户没 QPS？你在实验阶段就有数字：

    • 评测集大小、top1 命中率、faithfulness 分数（第 21 篇的 harness 跑出来）
    • 知识库文档页数、chunk 数、入库耗时
    • 单次问答 token 成本、Prompt caching 前后对比
    • 本地部署 TTFT/吞吐（第 24 篇 bench 跑出来）

    这些都是“你认真做过”的证据链。 面试官问细节时，能报出数字的人，和背概念的人，两轮问题就分出来了。

    Java 老司机对照室¶

    求职要素 你已经用过的 一句话翻译
    STAR 法则 晋升述职 / 项目复盘 情境-任务-行动-结果
    数字量化 性能优化汇报 没有数字等于没做
    技术选型理由 架构评审文档 为什么选它不选谁
    差异化叙事 跨部门协作自述 讲清“只有我能补的位”
    反诱导题 线上事故复盘 紧张处见真章
    面试反问环节 需求澄清习惯 问出对方的真痛点

    动手实验室¶

    实验 1：一段“工程经历 AI 化”改写（抄这个句式）¶

    改写前（平淡的 Java 履历）：

    负责订单系统重构，QPS 从 500 提升到 5000。

    改写后（工程底座 + AI 接合）：

    负责核心订单链路重构，QPS 500→5000、P99 从 800ms 降至 120ms； 2025 年起在链路中落地大模型能力：订单智能客服（RAG 接入商品知识库， 首解率 78%）及风控工单自动摘要（LLM 结构化抽取，人力环节缩短 65%）—— 上述能力基于公司现有 Java 网关嵌入，零新增微服务。

    看见句式了吗：老数字证明你的工程底子，新数字证明你的跨界落地，最后一句“嵌入现有架构”证明你不是愣头青。 一段话三层证据。

    实验 2：项目经历 STAR 模板¶

    ## 企业知识库 RAG 问答系统（Python / pgvector / LangGraph）

背景：内部 HR + 财务制度分散在 30+ 份文档，人工检索回答效率低、口径不一。

方案与行动：
- 文档流水线：按标题层级结构分块（512token/10%重叠），BGE-M3 向量化，
  幂等入库 pgvector 单表（千万级可行，未引入额外中间件）
- 检索链路：dense + BM25 混合召回，top50 预选后 cross-encoder 精排出 top5，
  相似度阈值拦截（<0.35 触发“资料未提及”）
- 生成链路：集中式 Prompt Registry 带版本灰度，答非所问类变更 5 分钟可回滚
- 质量体系：200 条评测集（正常/模糊/盲区/对抗四类），接 CI 分数门禁

结果：
- top1 命中率 94%，幻觉率较裸 Prompt 方案下降约 80%
- 单次问答综合成本 ¥0.012，Prompt 缓存命中后降至 ¥0.007
- 已支撑内部 3 个部门日常使用，累计 2 万次问答零事故

    数字按你的真实情况填，结构照抄。但有一条铁律：简历上写的每一项，面试时都要能被追问三层。 上面模板里的"混合召回 top50 + cross-encoder 精排"是工业界的完整形态——第 13/16 篇只带你手搓了纯向量检索（够用、够跑通、够进面试）。你想写进简历，就得自己动手补上那两层，或者：

    • 把简历改成你真做过的版本（"dense 检索 + 相似度阈值兜底"，一样有说服力）
    • 或者去补齐：uv add rank_bm25 sentence-transformers 半小时能加个 BM25 混合；cross-encoder 精排（BAAI/bge-reranker-base）多花一晚上

    "做过"和"听说过"在简历上长得一模一样，在面试的第 3 个问题里天差地别。 这是本书唯一一处要求你超出书本身动手的地方——也是从"读过"到"干过"的分界线。

    实验 3：面试十问速背卡¶

    1. “LLM 为什么会幻觉？怎么缓解？” → 08 篇的接话本质 + RAG + 指令约束 + 评测
    2. “RAG 召回率低怎么排查？” → 分块策略→embedding 适配→混合检索→精排，逐层定位
    3. “RAG 和微调怎么选？” → 18 篇的铁律：知识用 RAG，风格用微调
    4. “多轮对话成本怎么控？” → 17 篇历史压缩 + caching + 模型分级
    5. “Agent 怎么防止失控？” → max_iterations + 工具白名单 + HITL + 熔断
    6. “你 Java 经验在 AI 里的价值？” → 稳定性工程：限流降级、评测门禁、Prompt 版本化
    7. “Prompt Injection 怎么防？” → 12 篇的种子：指令分层、内容隔离、输入输出过滤
    8. “模型换成开源自部署，成本差多少？” → 显存成本 vs API 计费，讲 19 篇容量公式
    9. “怎么证明你的系统变好了？” → 21 篇评测集 + 前后对比，拒绝“感觉还行”
    10. “如果给你三个月从零搭？” → 直接讲本书 11→13→17 的路线，这就是你的施工图

    每道题的标准答案，都在前 19 篇里。 这就是本书的最后一层设计——它同时是一门课、一份笔记、一套面试弹药库。

    实验 4：一句反问定生死¶

    面试结尾别问“公司氛围怎么样”（浪费唯一提问）。问：

    “咱们 AI 应用目前最痛的点是效果不稳定，还是成本压不下来？团队对评测体系的建设到什么阶段了？”

    这个问题本身就在展示六个月的段位。 对方的回答还会告诉你：这家公司到底是认真做 AI 应用，还是赶风口——双向选择，也是你的护栏。

    费曼复述卡¶

    1. 用合同草稿的比喻，向朋友解释为什么“熟练掌握 Python”不值钱而“top1 命中率 94%”值钱。
    2. 三段式简历的三部分比例是什么？为什么 AI 项目不该超过工程经历的篇幅？
    3. 把 14 篇的 Agent 项目，用实验 2 的 STAR 模板改写成你自己的第一版项目经历（30 分钟内，写完贴到本书 Issue 区求review）。

    三题过不了——你大概还没开始写自己的简历。现在，合上书，打开文档，抄第一个字，比读懂十遍都值。

    今日一句话¶

    市场不为知识付钱，为“消除风险”付钱——你的工程履历不是过去式，是 AI 团队最缺的那味药。
