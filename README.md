## 一句话说明

**这本书记的不是大模型有多强，而是 Java 工程师的哪些老本行在 AI 时代突然变得值钱。**

限流、熔断、状态管理、评测、灰度、回滚——你写了十年的东西，正是AI 应用上线最缺的东西。
真正的竞争壁垒从来不是"会不会微调模型"，而是**"能不能把不稳定的模型能力，包装成稳定的线上服务"**。

## 作者是谁

一个写了多年 Java 8 的后端工程师。没有 AI 学历背景，也没有数学博士学位。

这本书的每一个结论都**在作者本机跑过并留下数据**（Apple M5 Pro / 24GB / 本地模型 + pgvector）：
检索 top1 **7/7**、SFT loss `6.443 → 0.777`、本地 4B 模型 RAG 问答 `0.2~2.3 秒/问`、0.5B 输出日文乱码的真实翻车现场……

**没有实测的结论，本书不写。** 判断一条经验值是"真跑出来的"还是"抄来的"，见[附录 B · 证据分级](docs/appendix-evidence-grading.md)。

## 为什么是 Java 程序员

这个群体正站在一个微妙的历史节点：

- 后端岗位在收缩，内卷加剧，CRUD 写不出溢价
- AI 应用岗位在爆发，但九成招聘要求写着"熟悉 Python"
- 大量 Java 工程师卡在"想转不敢转"：看不懂 Python 黑魔法，觉得大模型是高数家的游戏

而**把不稳定的模型能力包装成稳定的线上服务**——限流、熔断、状态管理、评测、灰度、回滚——
恰好是 Java 工程师练了十年的老本行。这本书要证伪的就是：**你不是从零开始，你只是换了一把剑。**

## 一份不一样的附录：AI 信息可信度分级手册（附录 B）

模型榜单月月换，这本书写于 2026 年 10 月。但有一件事不会过时：**怎么判断"新出的结论能不能信"。**

2026 年 10 月，一个只有 1 个月历史的新品类（决策模型）引发全网讨论。作者 review 后发现：最抢眼的那些跑分数字，可信度最低——因为它们全部来自被评测方自己。这件事催生了本书最独特的一章（附录 B），它教的是：

- **S/A/B/C/D 五级证据分级法**（区分"谁在说话、对手是否被打压、有没有第三方"）
- **决策模型事件的完整 review 记录**（哪些结论被引用、哪些跑分被拒绝，以及为什么）
- **半年后复盘约定**（2027 年 4 月回来看这个品类是否成立，判据就是这套分级）

**为什么说这是本书最值钱的部分**：技术细节两年后过时，但"厂商说自家模型打败对手时该信几分"这个能力，能让你在这个信息过载的行业里少踩十年的坑。

## 怎么用这本书

1. **按顺序读**。序号即依赖顺序，跳读容易在第四阶段迷路
